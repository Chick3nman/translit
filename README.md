# translit

**translit** converts between native-language text (Korean, Japanese, Chinese) and the
exact keystrokes a person produces when they type it with their input method switched
**off**. It is a streaming command-line filter built for password-recovery work with
[hashcat](https://hashcat.net/) and similar tools. These overlooked keystroke patterns
unlock a class of passwords that ordinary wordlists never reach.

| Looks like… | …is actually | Meaning | Typed on |
|---|---|---|---|
| `ji32k7au4a83` | 我的密碼 | "my password" | Zhuyin (Chinese) |
| `dkssud` | 안녕 | "hi" | Korean 2-beolsik |
| `tkfkdgo` | 사랑해 | "I love you" | Korean 2-beolsik |
| `byiaf` | こんにちは | "hello" | Japanese JIS kana |

## How it works

To type languages that don't fit a QWERTY keyboard, people use an **Input Method Editor
(IME)**: they type the *sounds* of a word and software assembles the right characters. The
IME is not always active. It can be disabled, not installed, or not engaged in a given
field such as a password box. When it is off, the characters are never formed, and what
gets stored and hashed is the **raw sequence of keys**. The result looks random but is
fully deterministic. The same phrase on the same layout always yields the same string, so
the *same* artifacts recur across breaches even though no English wordlist or mangling rule
produces them.

translit runs both directions:

- **Forward** (`-to keys`): native text → keystroke artifacts (crack candidates).
- **Reverse** (`-to native`): an observed artifact → candidate native text.

It is **blind and bulk** by design: it converts every line wherever it can, noise
included, and does not judge whether a line is "really" an artifact.

## Install

Requires [Go](https://go.dev/) 1.23+:

```sh
go build -o translit .
```

There are no external dependencies and no third-party data. The embedded Chinese and
Japanese reading sets are generated by this project. The build produces a single ~3.0 MB
binary.

## Languages and layouts

Names are case-insensitive. Each language has a default layout (✅).

| `-lang` (aliases) | `-layout` (aliases) | Default | Artifact |
|---|---|---|---|
| `korean` / `ko` | `2beolsik` | ✅ | gibberish (`안녕`→`dkssud`) |
| | `3beolsik` (`3f`, `sebeolsik-final`) | | gibberish (`안녕`→`jfshea`) |
| `japanese` / `ja` / `jp` | `jis-kana` | ✅ | gibberish (`こんにちは`→`byiaf`) |
| | `jis-kana-us` | | gibberish, US-keyboard variant (incomplete; see [Gotchas](#gotchas-and-limits)) |
| | `romaji` | | **readable** (`ねこ`→`neko`) |
| `zhuyin` / `zh` / `bopomofo` | `dacheng` (`大千`) | ✅ | gibberish (`我的密碼`→`ji32k7au4a83`) |
| | `eten` (`倚天`) | | gibberish, ETen layout (`我的密碼`→`xo3dr1me4ma3`) |

Two keyboards yield two artifacts for the same word. Pick the one matching the population
you are modeling.

## Usage

```
translit [-lang L] [-layout K] [-to D] [options] < input > output
```

Reads UTF-8 lines from **stdin**, writes to **stdout**, and sends diagnostics to **stderr**.
Everything is a flag (nothing positional). Exit status: `0` success, `2` bad
flag/language/layout, `1` runtime I/O error.

- **Passthrough**: characters a direction can't convert pass through unchanged, so mixed
  content works (`안녕1234!` → `dkssud1234!`).
- **Variants**: one input line may emit several output lines (Zhuyin reverse homophones,
  `-polyphone`, `-kanji`, `both`).
- **Dedup is per-line only**: a line never emits the same string twice, but there is no
  global dedup. Add `sort -u` if you need it.

### Directions (`-to`)

| `-to` | Meaning | Use |
|---|---|---|
| `keys` (default) | native → keystroke artifact(s) | generating crack candidates |
| `native` | artifact(s) → native text candidate(s) | decoding observed artifacts |
| `both` | run both directions on every line | when you don't know which a line is |

```sh
printf '안녕\n'   | translit -lang ko -to keys     # 안녕  -> dkssud
printf 'dkssud\n' | translit -lang ko -to native   # dkssud -> 안녕
```

### Options

| Flag | Scope | Default | Effect |
|---|---|---|---|
| `-lang <name>` | all | `korean` | source language |
| `-layout <name>` | all | per-language | keyboard layout |
| `-to <keys\|native\|both>` | all | `keys` | direction |
| `-keep-original` | all | off | also emit each input line before its conversion(s) |
| `-all` | all | off | **every** language, layout, and direction at once; ignores `-lang`/`-layout`/`-to`; kanji always on |
| `-kanji` | japanese | off | resolve kanji words to kana (forward); offer kanji for a kana reading (reverse) |
| `-polyphone` | zhuyin fwd | off | emit all readings of polyphonic chars, not just the primary |
| `-max-polyphone <N>` | zhuyin fwd | `0` | cap readings per polyphonic char under `-polyphone` (`0` = use `-max-readings`) |
| `-max-homophones <N>` | zhuyin rev | `20` | cap candidate chars per syllable |
| `-max-rank <N>` | zhuyin rev | `0` | restrict candidates to the top-N most frequent chars (`0` = all) |
| `-max-variants <N>` | ja/zh | `200` | cap total candidates per input line (explosion guard) |
| `-max-readings <N>` | ja/zh | `0` | cap readings per char/word (`0` = all, `1` = primary only) |
| `-tone1-space` | zhuyin fwd | `true` | emit a space for 1st-tone syllables (`台灣`→`w96j0 `) |
| `-version` | all | off | print version and exit |

Fan-out caps (`-max-variants`, `-max-homophones`) are hard guards clamped to ≥ 1, so a
stray `0` cannot disable them. Setting `-tone1-space=false` removes the delimiter that
reverse needs to segment 1st-tone syllables, which makes forward and reverse stop being
inverses.

### Per-language notes

**Korean**: Hangul ⇄ 2-beolsik / 3-beolsik Final. The mapping is fully algorithmic.
Forward is 1:1, and reverse recomposes via an IME-faithful automaton, so ordinary text
round-trips. NFD input is composed to NFC automatically. Shift surfaces as an uppercase key
(`깎`→`RkR`), and lone jamo work (`ㅋㅋㅋ`→`zzz`). Reverse is blind, so every lowercase
English word is a valid jamo sequence and decodes `password` to Hangul gibberish.

**Japanese**: `jis-kana` (default) and `jis-kana-us` model kana keyboards, where IME-off
output is gibberish and voiced kana expand to a base key plus a mark key (`が`→`t@`).
`romaji` types Latin directly and stays **readable** (`わたし`→`watashi`). Add `-kanji` to
resolve kanji on any layout. Resolution is word-level and compound-correct (今日 → きょう,
not こん+にち), and it greedily segments mixed kanji+kana (猫と犬 → nekotoinu). Reverse
offers candidate kanji for a whole kana reading.

```sh
printf '今日\n' | translit -lang ja -layout romaji -to keys -kanji   # -> kyou, ...
```

**Zhuyin (Chinese)**: Traditional Chinese ⇄ Dàqiān / ETen, dictionary-backed. Forward uses
each char's primary reading for one artifact unless `-polyphone` is set. Tones live on the
number row, and 1st tone is the space bar. Reverse is one-to-many across homophones: it
segments on tone keys and fans out, frequency-ranked and capped. Tune the yield with
`-max-homophones`, `-max-rank`, `-max-variants`, and `-max-readings`.

```sh
printf '我的密碼\n'     | translit -lang zh -to keys        # -> ji32k7au4a83
printf 'ji32k7au4a83\n' | translit -lang zh -to native      # -> 我的密碼, 我的密馬, ...
```

### hashcat workflows

```sh
# Generate a candidate file, then crack (best for fast hashes)
cat native_words.txt | translit -lang zh -to keys | sort -u > candidates.txt
hashcat -a 0 -m 1000 hashes.txt candidates.txt

# Stream directly (fine for slower hashes)
cat native_words.txt | translit -lang ja -layout romaji -to keys -kanji | hashcat -a 0 -m 0 hashes.txt

# Cover both the artifact and the original native word
cat native_words.txt | translit -lang ko -to keys -keep-original > candidates.txt

# Unknown or mixed input: run every language, layout, and direction
cat unknown.txt | translit -all | sort -u > candidates.txt

# Decode what you cracked, for reporting
cat cracked.txt | translit -lang zh -to native -max-homophones 5
```

### Gotchas and limits

- **Blind bulk**: output includes noise; the reverse of an English word is gibberish, not
  an error. Quality filtering of the output is out of scope.
- **Reverse passthrough is asymmetric**: reverse can only pass through characters that
  *aren't* valid keys, so `pass안녕`→`passdkssud` (forward) does not reverse back cleanly.
- **Round-trip** holds for ordinary text but not for standalone compound-final Korean jamo
  (`ㄳ`); Zhuyin and rōmaji are lossy by nature (homophones, `ん` ambiguity).
- **`jis-kana-us` is incomplete**: a US keyboard has fewer keys than JIS, so `む` is
  unreachable on reverse and some mark keys collide. Prefer `jis-kana` unless you
  specifically model US-keyboard users.
- **`-kanji` data** is embedded unconditionally but only *parsed* when the flag is set;
  reverse is whole-reading and won't segment a multi-word kana string.
